3. Tasks должны: скачать статику LightHouse, установить Nginx или любой другой веб-сервер, настроить его конфиг для открытия LightHouse, запустить веб-сервер.

5. Запустите `ansible-lint site.yml` и исправьте ошибки, если они есть.
6. Попробуйте запустить playbook на этом окружении с флагом `--check`.
7. Запустите playbook на `prod.yml` окружении с флагом `--diff`. Убедитесь, что изменения на системе произведены.
8. Повторно запустите playbook с флагом `--diff` и убедитесь, что playbook идемпотентен.

## Краткое описание playbook

### Что делает playbook?

Playbook автоматически разворачивает три сервиса на разных хостах:

1. **ClickHouse** - база данных для хранения логов (создает БД `logs`)
2. **Vector** - сборщик и маршрутизатор логов (отправляет демо-логи в ClickHouse)
3. **Lighthouse** - веб-интерфейс для мониторинга (nginx + статика)

### Параметры (переменные)

| Параметр | Что делает | Значение по умолчанию |
|----------|------------|----------------------|
| `clickhouse_version` | Версия ClickHouse | `22.8.9.24` |
| `clickhouse_architecture` | Архитектура системы | `amd64` |
| `vector_install_dir` | Папка установки Vector | `/opt/vector` |
| `vector_config_dir` | Папка конфигов Vector | `/etc/vector` |
| `lighthouse_repo` | Адрес репозитория Lighthouse | `https://github.com/VKCOM/lighthouse.git` |
| `lighthouse_version` | Ветка репозитория | `master` |

### Теги

В playbook нет явных тегов, но можно использовать стандартные ограничения по хостам:

| Команда | Что делает |
|---------|------------|
| `--limit clickhouse` | Установить только ClickHouse |
| `--limit vector` | Установить только Vector |
| `--limit lighthouse` | Установить только Lighthouse |
